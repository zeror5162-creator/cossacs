# Cossacks 3: власний мультиплеєр — дизайн

Дата: 2026-09-20
Статус: на розгляді

## 1. Мета

Дати гравцям Cossacks 3 (GOG/Steam) власну мультиплеєрну інфраструктуру:

- **кілька незалежних лобі-серверів** на нашому VPS плюс підтримка чужих серверів спільноти;
- **лаунчер `.exe`**: вибір сервера, огляд кімнат і гравців, пінг, запуск гри в один клік, автооновлення;
- **моніторинг**: публічний статус для лаунчера та адмін-панель з історією, графіками, кіком, баном і сповіщеннями в Telegram;
- **захищені ніки**: нік закріплюється за паролем, і бан діє на акаунт, а не лише на IP.

Критерії успіху:

1. Гравці, які зараз грають на `158.180.57.78:31523`, переходять на новий сервер **без змін у клієнті гри** і не помічають різниці в самій грі.
2. На одному процесі одночасно працюють щонайменше 2 наші сервери (різні порти) з незалежним станом.
3. Лаунчер показує онлайн, кімнати й пінг усіх серверів, наших і чужих, і запускає гру на вибраному.
4. Адмін бачить гравців з IP, може кікнути або забанити гравця й отримує в Telegram сповіщення про падіння серверів.

### Поза межами

- Зміни клієнта гри (`cossacks.exe`, скрипти меню) і клієнтські моди.
- Синхронізація модів і файлів гри через лаунчер.
- Реєстрація через сайт, e-mail, відновлення пароля (пароль ніку скидає адмін).
- Рейтинг, ладдер, статистика матчів (протокол це дозволяє, але зараз не робимо).
- Шифрування ігрового трафіку (клієнт говорить відкритим TCP, ми на це не впливаємо).
- Кілька адмінів з ролями.

## 2. Контекст

Детальний опис поточного стану — `cossacks3-server.md` (не в репозиторії). Коротко:

- Поточний сервер — [ereb-thanatos/cossacks3-lan-server](https://github.com/ereb-thanatos/cossacks3-lan-server): C++/ASIO, MIT. Протокол GSC відреверсований, формати описані коментарями в `src/Lobby.cpp`.
- Топологія — **зірка через сервер**: ігрові пакети пересилаються через лобі (хост кімнати → усім, гравець → хосту). NAT у гравців значення не має.
- Сервер не зберігає нічого на диск, не має автентифікації (нік береться з поля «ключ гри», e-mail і пароль ігноруються), порт `31523` захардкоджено.
- Клієнт читає адресу лобі з `data\resources\servers.dat`:
  ```
  section.begin
     * = 158.180.57.78:31523
  section.end
  ```
  Якщо рядків кілька, екран входу показує список `chooseserver` (`data\gui\menu.inc\showmultiplayerlogin.inc`). Для локалей `uk`/`ru` гра за замовчуванням вибирає **другий** рядок (`data\scripts\lib\profile.script`, `_profile_SetDefaultServerBasedOnLocale`).
- VPS: Oracle Always Free, **ARM64**, Ubuntu 24.04, вільно ~2.6 ГБ RAM. Хост спільний із приватним Minecraft-сервером, який має пріоритет. Відкриття порту вимагає двох кроків: Security List в OCI і правило iptables перед фінальним `REJECT`.

## 3. Архітектура

```
┌──────────────── VPS (ARM64) ────────────────────────────────┐
│  c3hub — один Go-бінарник, systemd-сервіс                   │
│                                                             │
│   lobby     N екземплярів, по одному на порт (31523, 31524…)│
│   store     SQLite: акаунти, бани, події, метрики           │
│   prober    опитування чужих серверів                       │
│   web :443  /api/servers (публічно), /admin (панель)        │
│   notify    Telegram                                        │
└─────────────────────────────────────────────────────────────┘
        ▲ TCP (гра)                        ▲ HTTPS
┌───────┴──────────────────────────────────┴──────────────────┐
│  ПК гравця: C3Launcher.exe → servers.dat → cossacks.exe     │
└─────────────────────────────────────────────────────────────┘
```

Рішення:

- **Лобі переписується на Go** (а не доробляється C++ форк і не ставиться проксі). Усе (лобі, бази, моніторинг, веб) живе в одному процесі й одній мові, стан лобі доступний моніторингу напряму. Ризик помилок при перенесенні закривається тестами паритету (розділ 9).
- **Один процес, кілька портів.** Кожен сервер — окремий екземпляр `lobby.Server` зі своїм станом. Паніка в обробнику одного з'єднання не зупиняє ні інших гравців, ні інші сервери, ні веб.
- **SQLite через `modernc.org/sqlite`** (чистий Go, без cgo), щоб крос-компіляція під `linux/arm64` з Windows працювала без тулчейнів.
- **HTTPS без домену**: хост `158-180-57-78.sslip.io` і сертифікат Let's Encrypt через `golang.org/x/crypto/acme/autocert`. Потрібні порти 80 (ACME HTTP-01 і редирект) та 443.
- **Бюджет пам'яті**: `MemoryMax=256M` у systemd, очікуване споживання 30–60 МБ.

## 4. Лобі-сервер

### 4.1 Протокол

Переноситься з `cossacks3-lan-server` без змін поведінки:

- заголовок 14 байт LE: `size u32` (довжина тіла), `cmd u16`, `id1 u32`, `id2 u32`;
- рядки з префіксом довжини 1/2/4 байти;
- максимальний розмір тіла `0x100000`;
- усі команди з `Lobby.cpp` (ігрові дані, логін/профіль, кімнати, чат, службові сповіщення) з тими самими правилами пересилання (`PropagateInRoom`, усім крім джерела, лише хосту);
- передача ролі хоста (`0x1bd`/`0x1be`), приховування кімнат із розпочатою грою.

Єдина навмисна зміна поведінки — логін (4.3).

### 4.2 Конфіг

`/etc/c3hub/config.toml` (на VPS, у репозиторії лише `deploy/config.example.toml`):

```toml
data_dir = "/var/lib/c3hub"

[web]
host = "158-180-57-78.sslip.io"
admin_password_hash = "$argon2id$..."

[telegram]
token = "..."
chat_id = 0
notify_players_threshold = 0      # 0 = вимкнено

[[server]]
name = "Основний"
port = 31523
protected_nicks = true
max_conn_per_ip = 4
description = "..."

[[server]]
name = "Турнір"
port = 31524
protected_nicks = true
max_conn_per_ip = 4
```

Зміна списку серверів застосовується перезапуском `c3hub`. Чужі сервери зберігаються в БД і керуються з адмінки.

### 4.3 Логін (`0x19a`)

Вхід: `ver1`, `ver2`, `email`, `password`, `game key`.

1. Нік = нормалізований `game key` (менше 4 символів доповнюється `_`, більше 16 обрізається, символи поза `a-zA-Z0-9()+-_.[]` замінюються на `_`), як в оригіналі.
2. Активний бан на IP або на нік → відмова.
3. Нік **зареєстрований**:
   - пароль збігається (argon2id) → вхід; якщо цей нік уже онлайн на цьому сервері, **стара сесія закривається** (як кік) і вхід дозволяється — для перепідключень гри;
   - інакше → відмова.
4. Нік **не зареєстрований**:
   - уже онлайн на цьому сервері → відмова;
   - пароль не порожній → нік реєструється з цим паролем, вхід;
   - пароль порожній → вхід гостем, нік не реєструється.
5. `protected_nicks = false` → кроки 3–4 пропускаються, діють лише бани й заборона дубліката.

Акаунти **спільні для всіх наших серверів**; бани можна видавати глобально або на конкретний сервер.

**Відмова** = закриття з'єднання після запису в журнал. Якщо в протоколі знайдеться відповідь-помилка з текстом, яку показує клієнт, використовується вона (з'ясовується під час реалізації; на решту дизайну не впливає).

### 4.4 Захист

- не більше `max_conn_per_ip` одночасних з'єднань з одного IP;
- з'єднання без успішного логіну закривається через 30 с;
- тіло пакета більше `0x100000` → закриття з'єднання;
- невідомі команди логуються й ігноруються (як в оригіналі).

### 4.5 Кік і бан

- **Кік** — закриття сесії; сервер обробляє його як звичайне від'єднання (включно з передачею ролі хоста).
- **Бан** — `{nick?, ip?, server? (null = усі), reason, expires_at? (null = назавжди), created_by}`. Під час видачі бану всі відповідні сесії кікаються одразу.

## 5. Сховище (SQLite)

Файл `/var/lib/c3hub/c3hub.db`, режим WAL, міграції вбудовані в бінарник.

| Таблиця | Поля (основні) |
|---|---|
| `accounts` | `nick` PK (без урахування регістру), `pass_hash`, `created_at`, `last_login_at`, `last_ip` |
| `bans` | `id`, `nick`, `ip`, `server_port`, `reason`, `created_at`, `expires_at`, `revoked_at` |
| `events` | `id`, `ts`, `server_port`, `type`, `nick`, `ip`, `data` (JSON) |
| `samples` | `ts`, `server_key`, `players`, `rooms`, `games`, `bytes_in`, `bytes_out` — щохвилини |
| `samples_hourly` | ті самі поля, агреговані (середнє й максимум) |
| `foreign_servers` | `id`, `name`, `host`, `port`, `enabled`, `added_at` |
| `probe_results` | `server_id`, `ts`, `status`, `latency_ms`, `players`, `rooms`, `snapshot` (JSON останнього стану) |
| `admin_sessions` | `token_hash`, `created_at`, `expires_at`, `ip` |

Типи подій: `login`, `login_denied`, `logout`, `room_create`, `game_start`, `kick`, `ban`, `unban`, `admin_login`.

Ретенція (щоденне завдання): `samples` — 7 днів, `samples_hourly` — 365 днів, `events` — 90 днів, `probe_results` — 30 днів.

## 6. Моніторинг

### 6.1 Свої сервери

Стан читається з пам'яті `lobby.Server` через знімок під м'ютексом. Раз на хвилину пишеться рядок у `samples`; погодинна агрегація виконується в кінці кожної години.

### 6.2 Пробер (чужі сервери)

- Раз на 2 хв на кожен увімкнений сервер: TCP-підключення (замір часу) → `0x19a` з ніком `[probe]` і версіями, які відправляє поточний клієнт → розбір `0x19b` (гравці, кімнати) → закриття. Таймаут 5 с.
- Статус: `online`, `offline`, `protocol_error`.
- Коли сервер `offline`, інтервал подвоюється до максимуму 10 хв; після першої успішної відповіді повертається до 2 хв.
- Пробер не бачить кімнат із розпочатою грою: оригінальний сервер їх ховає.

### 6.3 Сповіщення в Telegram

- Сервер (свій чи чужий) змінив статус `online` ↔ `offline`; для чужих — лише після 2 поспіль однакових результатів, щоб не спамити.
- Кік, бан, вхід в адмінку з IP, якого немає серед останніх 10 входів.
- Онлайн сервера досяг `notify_players_threshold` (якщо задано; не частіше ніж раз на 6 год).
- Падіння самого `c3hub`: `OnFailure=c3hub-alert.service` — одноразовий юніт, який шле повідомлення через `curl` з тим самим токеном.

Якщо Telegram не налаштований або недоступний, помилка логується, решта працює.

## 7. Веб

### 7.1 Публічний API

`GET /api/servers` — без авторизації, кеш 5 с:

```json
{
  "generated_at": "2026-09-20T18:00:00Z",
  "servers": [
    {
      "id": "own:31523",
      "name": "Основний",
      "host": "158.180.57.78",
      "port": 31523,
      "own": true,
      "status": "online",
      "uptime_s": 86400,
      "checked_at": "2026-09-20T18:00:00Z",
      "players": [{ "nick": "Taras", "state": "in_room" }],
      "rooms": [
        { "name": "2v2 0pt", "locked": false, "players": 3, "ai": 0,
          "max": 8, "in_game": false, "historical": false }
      ]
    }
  ]
}
```

- `state` гравця: `lobby`, `in_room`, `host`, `playing`.
- **IP гравців і паролі кімнат ніколи не віддаються.**
- Для чужих серверів `uptime_s` відсутній, а `checked_at` — час останньої проби.

`GET /healthz` — `200`, якщо всі наші слухачі живі.

### 7.2 Адмін-панель `/admin`

Серверний рендер: Go `html/template` + htmx + uPlot, статика вбудована через `embed`.

- **Вхід**: один адмін, хеш пароля в конфігу. Сесійна cookie (`HttpOnly`, `Secure`, `SameSite=Strict`), 30 днів. CSRF-токен на всіх POST. Після 5 невдалих спроб з IP вхід блокується на 15 хв.
- **Огляд**: картки всіх серверів (статус, онлайн, кімнати); графік онлайну за 24 год / 7 днів / 30 днів.
- **Сервер**: живі гравці (нік, IP, статус, час входу) і кімнати; кнопки «Кік» і «Бан»; оновлення кожні 5 с.
- **Гравці**: пошук за ніком, історія входів (час, IP, сервер), скидання пароля (нік знову стає вільним), бан.
- **Бани**: список з фільтрами, видача й зняття бану.
- **Журнал**: `events` з фільтрами за сервером, ніком, типом і датою.
- **Чужі сервери**: додавання, вимкнення, видалення; графік доступності й онлайну.

## 8. Лаунчер

C# .NET 8, WPF, single-file self-contained `C3Launcher.exe` (win-x64), інтерфейс українською. Налаштування й кеш — `%APPDATA%\C3Launcher\`.

- **Пошук гри**: реєстр GOG (`HKLM\SOFTWARE\WOW6432Node\GOG.com\Games\1797227701`, значення `path`), потім Steam; якщо не знайдено — діалог вибору папки. Папка валідна, якщо в ній є `cossacks.exe` і `data\resources\`.
- **Головне вікно**:
  - таблиця серверів: назва, статус, гравці, кімнати, пінг;
  - дані беруться з `GET /api/servers` кожні 15 с;
  - пінг — локальний TCP connect до `host:port` (без логіну), паралельно, кожні 30 с;
  - панель вибраного сервера: кімнати (назва, замок, гравці/ШІ, «йде гра») і список гравців.
- **Без API**: показується закешований останній список, пінг працює, зверху банер «Статус серверів недоступний».
- **«Грати»**:
  1. Якщо `cossacks.exe` уже запущений — попередження, запуск не виконується.
  2. Перед першим записом `servers.dat` копіюється в `servers.dat.c3launcher-backup` (якщо такої копії ще нема).
  3. `servers.dat` перезаписується **одним рядком** з вибраним сервером (ASCII, CRLF, без переносу в кінці).
  4. Запуск `cossacks.exe` з робочою папкою гри.
- **Підказка** біля кнопки: нік вводиться в поле «ключ гри», пароль закріплює нік.
- **Автооновлення**: при старті `GET https://api.github.com/repos/zeror5162-creator/cossacs/releases/latest`. Якщо версія новіша за поточну, завантажує `C3Launcher.exe` і `C3Launcher.exe.sha256`, звіряє хеш, перейменовує поточний файл на `.old`, кладе новий, перезапускається; `.old` видаляється при наступному старті. Помилка оновлення не блокує роботу.
- **Меню**: «Відновити оригінальний servers.dat», «Змінити папку гри».

Адреса API вшита в збірку (`https://158-180-57-78.sslip.io/api/servers`) з можливістю перевизначення в налаштуваннях.

## 9. Тестування

### Сервер

- **Юніт-тести `protocol`**: розбір і серіалізація заголовка й рядків, межові розміри, обрізані пакети.
- **Юніт-тести `auth`**: усі гілки 4.3 (зареєстрований/ні, пароль правильний/ні/порожній, дублікат, бани на нік/IP/сервер, прострочені бани).
- **Тести паритету з оригіналом** — головний захист від помилок перенесення:
  - debug-збірка C++ сервера (без `-DNDEBUG`) запускається в тестовому оточенні;
  - сценарії (кілька клієнтів: логін → створення кімнати → вхід → чат → налаштування → старт → ігрові дані → вихід хоста → передача ролі → вихід) проганяються **однаково** проти C++ і Go-сервера;
  - відповіді порівнюються байт у байт з нормалізацією лише полів, що залежать від часу або порядку призначення id;
  - сценарії зберігаються в `server/testdata/parity/` і запускаються в CI (Linux).
- **Інтеграційні тести `web`**: API не містить IP і паролів; адмінка вимагає сесію й CSRF.
- **Ручний прийомний тест**: 2–4 реальних гравці проводять партію на тестовому порту до перемикання продакшну.

### Лаунчер

- Юніт-тести: запис `servers.dat` (байти файлу), розбір відповіді API, порівняння версій, звірка SHA-256.
- Ручна перевірка: перший запуск без гри, з GOG, запуск гри, оновлення зі старішої версії.

## 10. Розгортання

- Збірка сервера на ПК: `GOOS=linux GOARCH=arm64 CGO_ENABLED=0 go build`; доставка через `scp` у `/opt/c3hub/`.
- Користувач `c3hub` (system, nologin); `/var/lib/c3hub` (дані), `/etc/c3hub` (конфіг, `0640 root:c3hub`).
- `c3hub.service`: `Restart=always`, `MemoryMax=256M`, `AmbientCapabilities=CAP_NET_BIND_SERVICE` (для 80/443), `ProtectSystem=strict`, `ReadWritePaths=/var/lib/c3hub`, `OnFailure=c3hub-alert.service`.
- `c3hub` додається у виключення `needrestart`, щоб оновлення бібліотек не викидали гравців. **Потрібен дозвіл користувача**: `/etc/needrestart/` входить у список «не чіпати без дозволу».
- Порти: 80, 443 і нові ігрові порти відкриваються в iptables (перед `REJECT`, `netfilter-persistent save`) і **користувачем** у Security List OCI.
- **Міграція**:
  1. `c3hub` запускається на тестовому порту (31524), старий `cossacks3.service` працює далі на 31523.
  2. Прийомний тест з реальними гравцями на 31524.
  3. `cossacks3.service` зупиняється й вимикається (не видаляється), `c3hub` отримує 31523.
  4. Відкат — зворотна заміна.
- Лаунчер: `dotnet publish -c Release -r win-x64 --self-contained -p:PublishSingleFile=true`, реліз на GitHub із `.exe` і `.sha256`.
- **Секрети** (токен Telegram, хеш пароля адміна, БД) ніколи не потрапляють у репозиторій: він публічний.

## 11. Ризики й відкриті питання

| Ризик | Що робимо |
|---|---|
| Розбіжність Go-порту з оригіналом ламає гру | Тести паритету + прийомний тест до перемикання; C++ сервер лишається для відкату |
| Відмова в логіні виглядає для гравця як «не вдалося підключитися» | Шукаємо в протоколі пакет помилки; інакше пояснення в лаунчері й в описі сервера |
| Чужі адміни незадоволені `[probe]` в лобі | Інтервал 2 хв, миттєвий вихід; вимикач для кожного чужого сервера |
| sslip.io або Let's Encrypt недоступні | Лаунчер працює з кешем і власним пінгом; сертифікат оновлюється заздалегідь (autocert, за 30 днів) |
| Тиск на RAM спільного хоста | `MemoryMax=256M`, без навантажувальних тестів на VPS |
| Невідомо, чи клієнт пропускає `0x1ad` до логіну (для health-check) | Не потрібен: свої сервери перевіряються зсередини, чужі — повним логіном |

## 12. Етапи

Кожен етап має окремий план реалізації й закінчується робочим результатом:

1. **Лобі на Go** — `protocol`, `lobby`, кілька портів, тести паритету, розгортання на тестовому порту. Результат: повноцінна заміна C++ сервера.
2. **Акаунти, бани, моніторинг, адмінка, Telegram, пробер, публічний API**. Результат: перемикання продакшну на `c3hub`.
3. **Лаунчер** з автооновленням і першим релізом на GitHub.
